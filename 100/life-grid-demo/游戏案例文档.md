# 人生选择器（Life Grid）游戏案例文档

> 本案例文档面向游戏开发者，系统介绍《人生选择器》的创作背景、核心原理、功能特性与实现方法，帮助你理解并复刻这款基于 10×10 风险决策网格的人生经营模拟游戏。

---

## 一、项目概述

**人生选择器（Life Grid）** 是一款以「人生 = 时间 × 选择 × 概率」为核心理念的人生经营模拟游戏。玩家从 1 岁开始，每年只能进行一次关键人生选择。每次选择都会触发结果判定，影响财富、健康、知识、技能、社交、幸福、魅力、运势等属性，最终形成独一无二的人生轨迹，并在生命结束时生成人生能量曲线与最终评价。

项目包含两个运行版本：

- **终端版（`src/index.ts`）**：用于快速验证核心逻辑，可自动模拟 120 年人生并输出 ASCII 结算界面。
- **Web 交互版（`src/web/main.ts`）**：基于 Vite + TypeScript 的浏览器可交互版本，支持 10×10 网格点击、行为弹窗、日志面板、能量曲线图表、人生保存/加载/回放、规则编辑、行为库编辑等功能。

项目还提供两种游戏模式：

- **现代社会模式（modern）**：模拟从幼儿到暮年的现代人生，行为库覆盖成长、教育、事业、投资、感情、家庭、社交、兴趣、风险、机遇十大类别（当前实现约 126 个行为）。
- **末世生存模式（apocalypse）**：将人生舞台搬到废土/末世，行为以生存、探索、建造、战斗、交易、势力经营为主（当前实现约 62 个行为，设计规划中约 180 个）。

## 二、创作背景与设计目标

### 2.1 创作背景

人生选择器的灵感来源于对人生不确定性的抽象：

- 每个人每年都在做选择，但无法精确控制结果；
- 风险与收益往往正相关，高风险可能带来高回报，也可能带来重创；
- 人生的幸福不只取决于财富，还取决于健康、关系、成长与内心平衡；
- 成功与失败会形成惯性，连续成功会提升信心和运势，连续失败会陷入恶性循环。

游戏试图用极简的「每年一次选择」机制，把这些人生体验压缩成一个可重复游玩、可观察、可回放的模拟器。

### 2.2 设计目标

1. **低门槛，高重玩价值**：规则简单到一句话能说清，但每局人生都因随机性、玩家选择而不同。
2. **风险可视化**：通过 10×10 网格让玩家直观看到「越往上风险越高、收益越大」。
3. **年龄成长感**：低龄时选择少、风险低；成年后选择面逐渐展开，高风险高回报行为出现。
4. **避免无脑策略**：通过生态平衡度、连锁反馈、死亡模型等机制，惩罚偏科和过度冒险。
5. **可扩展的数据驱动架构**：行为库、事件库、年龄配置、游戏规则均独立于核心逻辑，便于后续扩展题材和调优数值。

## 三、核心玩法原理

### 3.1 10×10 风险决策网格

游戏棋盘是一个 10×10 的网格：

- **Y 轴（n1 ~ n10）**：风险等级。n1 在最底部，代表极低风险、低收益、低失败惩罚；n10 在顶部，代表极高风险、高收益、高失败惩罚。
- **X 轴（l1 ~ l10）**：行为类别分区，依次为成长、教育、事业、投资、感情、家庭、社交、兴趣、风险、机遇。

每一年，系统会根据玩家当前年龄、财富、状态生成一个可选行为池，并将这些行为按风险等级放入网格中。玩家点击某个格子，即选择该行为。

> 注意：10×10 网格不是按年龄分列的时间轴，而是**每一年当前可选行为的二维展示**。低龄时只有底部几行有内容，成年后网格逐渐填满。

### 3.2 一年一选择的核心循环

```
年龄增长
  ↓
根据年龄/财富/状态生成行为池
  ↓
将行为池映射到 10×10 网格
  ↓
玩家点击网格选择行为
  ↓
弹出行为详情与确认
  ↓
结果判定（大成功/成功/普通/失败/大失败）
  ↓
触发随机事件
  ↓
更新玩家属性
  ↓
更新生态平衡度与连锁状态
  ↓
死亡判定
  ↓
记录人生轨迹
  ↓
进入下一年
```

### 3.3 结果判定公式

结果判定是游戏最核心的随机机制：

```
Score = behavior.rewardLevel × riskLevel × attrMultiplier × randomFactor × balancePenalty × chainFactor
```

其中：

- `rewardLevel`：行为本身的收益基数，由数据配置。
- `riskLevel`：玩家选择的网格 Y 坐标，即风险等级（1~10）。
- `attrMultiplier`：属性修正。行为标签匹配玩家属性时获得加成，例如「知识」标签受知识属性加成，「财富」标签受财富加成。
- `randomFactor`：随机因子，范围 0.5 ~ 2.0，模拟人生不确定性。
- `balancePenalty`：生态平衡惩罚。当 `lifeBalance < 30` 时，惩罚为 0.7。
- `chainFactor`：连锁因子。连续成功时放大收益，连续失败时缩小收益。

系统将该 Score 与行为的期望收益对比，得出结果档位：

| 结果档位 | 判定条件（相对期望收益） | 主要影响 |
|---|---|---|
| 大成功（bigSuccess） | ratio ≥ 2.0 | 财富、属性大幅提升，运势增加 |
| 成功（success） | 1.2 ≤ ratio < 2.0 | 正常收益 |
| 普通（normal） | 0.7 ≤ ratio < 1.2 | 变化较小 |
| 失败（failure） | 0.3 ≤ ratio < 0.7 | 资源损失，幸福/健康下降 |
| 大失败（bigFailure） | ratio < 0.3 | 重创，多项属性大幅下降 |

### 3.4 八大显性属性

玩家状态包含以下显性属性：

| 属性 | 含义 | 主要获取方式 |
|---|---|---|
| 健康（health） | 生命值，0~100 | 成长类、健康类行为；会随年龄自然衰减 |
| 财富（wealth） | 金钱与资产 | 事业、投资类行为；大成功时巨额增长 |
| 知识（knowledge） | 学识水平，0~100 | 教育类行为 |
| 技能（skill） | 实践能力，0~100 | 事业、技能类行为 |
| 社交（social） | 人脉关系，0~100 | 社交、家庭类行为 |
| 幸福（happy） | 心理状态，0~100 | 感情、家庭、兴趣类行为 |
| 魅力（charm） | 个人魅力，0~100 | 兴趣类行为；有生命周期曲线 |
| 运势（luck） | 随机事件触发概率 | 成功提升，失败降低；每年自然波动 |

### 3.5 隐性系统属性

| 属性 | 作用 |
|---|---|
| 生态平衡度（lifeBalance） | 衡量人生是否失衡。偏科行为会降低平衡度，平衡度低于 30 时结果恶化、危机事件增加。 |
| 成功链（successChain） | 连续成功次数。影响解锁高阶行为、降低死亡概率、提升运势。 |
| 失败链（failureChain） | 连续失败次数。会导致可选行为减少、只能选低风险行为、增加危机事件。 |
| 死亡概率（deathRate） | 当年基础死亡概率，受年龄、健康、平衡、连锁、风险修正。 |

## 四、关键子系统设计

### 4.1 行为池生成系统

每一年，系统会按以下步骤生成当前可选行为池：

1. **年龄过滤**：只保留 `minAge ≤ age ≤ maxAge` 的行为。
2. **风险上限过滤**：根据年龄段配置，过滤掉超过 `maxRisk` 的行为。例如 1~5 岁最高只能出现 n3 行为。
3. **类别过滤**：根据人生阶段开放不同类别。例如幼儿期不开放事业、投资。
4. **财富加成**：成年以后，财富越高，可选行为数量越多。
5. **失败链限制**：连续失败 ≥3 次时，只能选 n3 及以下低风险行为。
6. **成功链奖励**：连续成功 ≥3 次时，解锁高风险高收益行为。
7. **轮询采样**：按 10 大类别轮流抽取，确保类别均衡。
8. **保底机制**：即使过滤后行为极少，也至少保证 3 个可选行为，避免游戏锁死。

年龄段配置示例（见 `src/data/age-config.ts`）：

| 年龄段 | 保底数量 | 风险上限 | 财富加成阈值 |
|---|---|---|---|
| 1~5 岁 | 4 | n3 | 无 |
| 6~12 岁 | 5 | n4 | 无 |
| 13~18 岁 | 6 | n5 | 无 |
| 19~30 岁 | 7 | n8 | 每 10 财富 +1 |
| 31~50 岁 | 7 | n9 | 每 50 财富 +1 |
| 51~70 岁 | 6 | n8 | 每 100 财富 +1 |
| 71 岁以上 | 5 | n6 | 每 50 财富 +1 |

### 4.2 生态平衡度系统

生态平衡度是防止玩家无脑偏科的隐性裁判：

- 每个行为有 `balanceEffect`，决定执行后对平衡度的基础影响。
- 连续重复执行同一行为，平衡度额外下降。
- 结果越好，平衡度越高；结果越差，平衡度越低。
- 财富远超健康（`wealth > health × 1000`）或幸福过低（`happy < 20`）时，平衡度额外下降。

当 `lifeBalance < 30` 时，结果判定获得 0.7 的惩罚系数，危机事件概率也提升。

### 4.3 连锁反馈系统

成功和失败都会形成自我强化的连锁：

```
大成功/成功：
  successChain +1，failureChain 清零
  deathRate × 0.95
  luck +1

大失败/失败：
  failureChain +1，successChain 清零
  deathRate × 1.1
  luck -2

普通结果：
  两个连锁都缓慢衰减到 0
```

连锁不仅影响数值，还会通过行为池生成系统改变玩家下一年的可选范围。

### 4.4 死亡判定模型

死亡判定由重大疾病系统和自然衰老死亡共同组成：

#### 重大疾病系统

- **40~59 岁**：每年有 4% 概率突发重疾；重疾后医治无效则死亡，否则健康/财富大幅下降。
- **60 岁以上**：每年有 80% 概率陷入重病或身体机能衰竭；死亡概率显著上升。
- 治疗效果由健康、财富、运势共同决定：治疗效果越好，死亡概率越低，康复概率越高。
- 已患重病时，每年可能康复、带病维持或死亡。

#### 自然衰老死亡

当没有重大疾病时，按年龄基础概率判定自然死亡：

| 年龄 | 基础死亡率 |
|---|---|
| 1 岁 | 0.01% |
| 20 岁 | 0.05% |
| 40 岁 | 0.1% |
| 60 岁 | 1% |
| 80 岁 | 10% |
| 100 岁 | 70% |
| 110 岁 | 95% |

中间年龄通过线性插值计算。

#### 死亡原因叙事

Web 版会根据玩家最终状态、最后行为、触发事件生成具体的死亡原因文案，例如「寿终正寝」「重疾不治」「意外事故」「积劳成疾」等，增强叙事感。

### 4.5 随机事件系统

事件在游戏中有两个触发时机：

- **回合开始事件**：时代事件、家庭事件、健康事件等。
- **行为结算后事件**：幸运事件、危机事件、财富事件等。

事件有基础权重，并受玩家状态修正：

- 幸运事件权重随 `successChain` 和 `luck` 提升。
- 危机事件权重随 `failureChain` 和 `100 - lifeBalance` 提升。
- 系统保留约 60% 的不触发概率，避免事件过于频繁。

### 4.6 年龄自然衰减

随着年龄增长，玩家会面临自然衰退：

- **50 岁后**：健康每年缓慢下降。
- **80 岁后**：健康额外加速下降。
- **100 岁后**：健康大幅下降，确保极少能活到最大年龄上限。
- **30 岁后**：幸福每年自然下降 1 点，需要积极行为维持。
- **魅力**：0~50 岁成长，50 岁后衰退，形成生命周期曲线。
- **运势**：每年在 -10 ~ +10 之间随机波动。

## 五、功能特性

### 5.1 终端版功能

- 自动模拟完整人生（默认 120 年）。
- 每回合输出网格状态、选择行为、结果、触发事件。
- 生命结束时输出 ASCII 结算界面，包括：
  - 最终年龄与主要属性
  - 人生评价（富有、传奇、幸福、痛苦、孤独、贫困、平凡等）
  - 能量曲线折线图
  - 重要人生节点（大成功/大失败）

### 5.2 Web 交互版功能

- **10×10 可点击网格**：按风险等级着色，hover 显示行为名称，点击弹出详情。
- **行为详情弹窗**：显示名称、描述、风险等级、预计收益、成功概率、确认按钮。
- **属性面板**：实时显示年龄、健康、财富、知识、技能、社交、幸福、魅力、运势、生态平衡度、成功/失败链。
- **年度总结**：显示上一年度主要属性变化及原因。
- **日志面板**：逐年记录选择、结果、触发事件、属性变化。
- **能量曲线图表**：Canvas 实时绘制人生能量变化曲线。
- **多属性曲线图**：同时展示健康、财富、知识、技能、社交、幸福、魅力、运势的历年变化。
- **人生阶段切换**：可查看不同人生阶段（出生、成长、工作、家庭、中年、晚年、终点）的行为库。
- **自动人生**：按选定速度自动选择行为并推进。
- **规则编辑**：在状态面板中动态调整游戏规则参数，持久化到 localStorage。
- **行为库编辑**：支持按类别覆盖/编辑行为数据，实时生效。
- **保存人生**：将当前人生导出为 JSON 文件或保存到 localStorage 存档槽。
- **加载人生**：从本地存档或 JSON 文件导入人生数据。
- **回放人生**：按年逐步回放已保存的人生，回放结束后状态与原人生一致。
- **自动人生案例**：可预生成示例人生案例并打包到 Web 产物中。

## 七、数据设计

### 7.1 行为节点结构

每个行为是一个 JSON/TypeScript 对象，包含以下字段：

```ts
interface Behavior {
  id: string;                    // 唯一标识
  name: string;                  // 行为名称
  category: string;              // 类别：成长、教育、事业、投资、感情、家庭、社交、兴趣、风险、机遇
  minAge: number;                // 最低可执行年龄
  maxAge: number;                // 最高可执行年龄
  riskLevel: 1 | 2 | ... | 10;   // 风险等级，决定网格 Y 轴位置
  rewardLevel: number;           // 收益基数
  failureLevel: number;          // 失败惩罚基数
  balanceEffect: number;         // 对生态平衡度的影响
  unlockWealth: number;          // 解锁所需财富门槛（0 表示无门槛）
  tags: string[];                // 标签，用于属性修正
  description: string;           // 描述文案
  narrative?: {                  // 叙事文本（可选）
    title: string;
    story: string;
    successText: string;
    failureText: string;
    normalText?: string;
  };
}
```

### 7.2 行为库设计原则

1. **按真实人生阶段划分**：避免 1 岁做饭、演讲、投资、买房等不合理选项。
2. **类别与标签一致**：例如健康类行为应带有「健康」标签，避免属性修正错位。
3. **风险与收益匹配**：高风险行为应有更高 `rewardLevel`，但也有更高 `failureLevel`。
4. **保底与解锁兼顾**：每个年龄段都有足够且合理的可选行为，财富可解锁更多高阶行为。
5. **叙事增强代入感**：为关键行为配置 `narrative` 字段，提升游戏叙事感。

### 7.3 事件结构

```ts
interface GameEvent {
  id: string;
  type: 'lucky' | 'normal' | 'crisis' | 'era' | 'family' | 'health' | 'wealth';
  title: string;
  description: string;
  narrative?: string;
  minAge?: number;
  maxAge?: number;
  effects: EffectSnapshot;
  weight: number;
}
```

### 7.4 行为库扩展建议

- **现代社会库**：已实现约 126 个行为，覆盖十大类别与七个年龄段，接近 150 个的规划目标。
- **末世库**：当前已实现约 62 个核心行为，另有设计文档规划约 180 个，重点放在生存、探索、建造、战斗、交易、势力经营。
- 新增题材时，建议复制一份行为数据文件，调整 `category`、`tags`、`narrative` 即可复用核心规则。

## 八、开发指南：如何复刻这款游戏

### 8.1 最小可玩版本开发步骤

如果你要从零复刻人生选择器，建议按以下顺序实现：

#### 第一步：定义核心数据结构

1. 定义 `Behavior` 接口，包含 id、name、category、minAge、maxAge、riskLevel、rewardLevel、failureLevel、balanceEffect、tags 等字段。
2. 定义 `PlayerState` 接口，包含 age、health、wealth、knowledge、skill、social、happy、charm、luck、lifeBalance、successChain、failureChain、history 等字段。
3. 定义 `ResultType` 类型：`'bigSuccess' | 'success' | 'normal' | 'failure' | 'bigFailure'`。

#### 第二步：实现行为池生成

1. 根据当前年龄过滤行为库。
2. 按年龄段配置限制 `maxRisk` 和 `baseCount`。
3. 按类别轮询采样，确保类别均衡。
4. 加入财富加成、失败链限制、成功链奖励。
5. 保底至少 3 个可选行为。

#### 第三步：实现结果判定

1. 实现 `resolveResult(behavior, riskLevel, state)`。
2. 计算属性修正、随机因子、平衡惩罚、连锁因子。
3. 将 Score 映射为 5 档结果。

#### 第四步：实现属性效果

1. 根据结果档位和行为标签，计算各属性变化。
2. 应用到 `PlayerState`。
3. 实现属性上下限限制（clamp）。

#### 第五步：实现平衡度与连锁

1. `updateLifeBalance`：根据行为 balanceEffect、结果、重复行为、极端属性更新平衡度。
2. `updateChains`：根据结果更新 successChain/failureChain，并影响 deathRate 和 luck。

#### 第六步：实现死亡判定

1. 基础年龄死亡率表。
2. 重大疾病系统（可选，但强烈建议）。
3. 自然衰老死亡判定。

#### 第七步：实现主循环

```
创建初始状态
while (未死亡 && 年龄 < 最大年龄) {
  生成行为池
  渲染网格
  获取玩家选择
  判定结果
  应用效果
  更新平衡度与连锁
  触发事件
  记录历史
  死亡判定
  年龄增长，应用衰老
}
输出结算
```

#### 第八步：实现 UI

1. 10×10 网格渲染，按风险等级排列。
2. 行为详情弹窗。
3. 属性面板、日志面板。
4. 能量曲线图表。
5. 结算界面。

#### 第九步：实现存档/回放

1. 导出 `SavedLifeData`：包含 version、config、records、snapshots、savedAt。
2. 导入时校验版本、配置、快照数量。
3. 回放时按快照精确恢复状态。

### 8.2 数值调优建议

1. **先让一局能跑通**：使用较小的行为库（30~50 个）和较短的寿命（30~50 岁）快速验证。
2. **观察能量曲线**：能量曲线应呈现明显的起伏，而不是单调上升或下降。
3. **测试偏科策略**：例如只选投资、只选健康，观察是否会被平衡度系统惩罚。
4. **测试失败螺旋**：连续失败时，玩家应能感受到选择受限，但不应完全无法翻身。
5. **调整死亡概率**：如果玩家普遍活不到老年，降低基础死亡率或提升治疗效果；如果普遍活到最大年龄，提高老年衰减。
6. **调整财富增长**：如果财富增长过快，降低 `bigSuccessWealthMultiplier`；如果过慢，提高 `successWealthBaseMultiplier`。

### 8.3 扩展方向

1. **新题材模式**：复制 `modern-behaviors.ts` 为 `fantasy-behaviors.ts`、`cyberpunk-behaviors.ts` 等。
2. **成就系统**：根据人生轨迹解锁成就，例如「亿万富翁」「百岁老人」「情场失意」等。
3. **关系系统**：增加父母、伴侣、子女、朋友等 NPC 关系，影响事件和行为效果。
4. **时代系统**：每隔几十年触发一次时代事件，改变全局规则。
5. **多周目继承**：上一局的部分属性或成就可继承到下一局。
6. **AI 对手/排行榜**：展示其他玩家的人生轨迹和能量曲线。
