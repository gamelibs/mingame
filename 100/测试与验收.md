# 人生选择器 - 测试机制与验收标准

> 本文档定义 Life Grid（人生选择器）项目的测试策略、测试用例、运行方式及验收标准。
>
> 目标：确保核心逻辑正确、行为数据合理、UI 渲染准确，在不同年龄段都能提供符合现实的人生模拟体验。

---

## 一、测试原则

1. **数据驱动优先**：行为库、事件库、年龄配置是项目的核心数据，必须先通过数据合法性测试。
2. **年龄合理性是底线**：人生模拟游戏的核心沉浸感来自「不同年龄出现不同行为」，必须严格校验。
3. **坐标系一致性**：棋盘 `n1` 必须在底部、`n10` 必须在顶部，`l1 ~ l10` 必须对应 10 大类别。
4. **自动化为主**：所有核心测试均通过 `npm run test` 一键运行，避免人工逐页检查。
5. **构建即验收**：TypeScript 编译、Web 生产构建、终端版运行均不得报错。

---

## 二、测试分类

### 2.1 数据加载测试（test-data）

**目标**：验证行为库、事件库、年龄配置、死亡率表的数据完整性。

**测试文件**：`life-grid-demo/src/test-data.ts`

**测试项**：

| 编号 | 测试项 | 通过标准 |
|---|---|---|
| D-01 | 现代行为库数量 | `modernBehaviors.length >= 60` |
| D-02 | 末世行为库数量 | `apocalypseBehaviors.length >= 60` |
| D-03 | 事件库数量 | `gameEvents.length >= 30` |
| D-04 | 现代行为库覆盖年龄段 | 1-5、6-12、13-18、19-30、31-50、51-70、71+ 每个年龄段至少有 1 个行为 |
| D-05 | 末世行为库覆盖年龄段 | 同上 |
| D-06 | 年龄段配置可读性 | `getAgeConfig(age)` 对每个测试年龄返回合法配置 |
| D-07 | 死亡率单调递增 | 同一人状态下，年龄越大死亡率越高 |

**运行命令**：

```bash
cd life-grid-demo
npm run test-data
```

---

### 2.2 核心逻辑测试（test-core）

**目标**：验证状态机、行为池生成、结果判定、死亡判定等核心算法。

**测试文件**：`life-grid-demo/src/test-core.ts`

**测试项**：

| 编号 | 测试项 | 通过标准 |
|---|---|---|
| C-01 | 初始状态合法 | 年龄=1，健康=100，财富=0，历史为空 |
| C-02 | 低龄行为池数量与风险 | 1 岁行为池 3~5 个，所有行为 riskLevel <= 3 |
| C-03 | 成年行为池更丰富 | 30 岁行为池数量大于 1 岁 |
| C-04 | 结果判定多档位 | `resolveResult` 多次调用产生至少 2 种结果档位 |
| C-05 | 死亡率随年龄增长 | 高龄状态死亡率高于年轻状态 |
| C-06 | 死亡判定可执行 | `checkDeath` 能正常返回布尔值 |

**运行命令**：

```bash
cd life-grid-demo
npm run test-core
```

**目标**：验证终端版网格渲染、坐标解析、行为弹窗、模拟选择等 UI 逻辑。

**测试文件**：`life-grid-demo/src/test-ui.ts`

### 2.4 年龄合理性测试（test-age）

**目标**：确保不同年龄段只会出现合理的行为，不会出现「1 岁做饭/演讲/投资」等破坏沉浸感的内容。

**测试文件**：`life-grid-demo/src/test-age-appropriateness.ts`

**测试项**：

| 编号 | 测试项 | 通过标准 |
|---|---|---|
| A-01 | 全年龄段行为池合法 | 每个测试年龄段行为池数量 >= 3，且所有行为年龄范围匹配 |
| A-02 | 1-5 岁类别限制 | 只允许 成长/教育/家庭/兴趣/风险/机遇，不含做饭、演讲、房屋漏水、买股票、买房、创业、工作等 |
| A-03 | 6-12 岁类别限制 | 不出现事业/投资/感情类成人行为 |
| A-04 | 13-18 岁限制 | 不出现高阶投资、结婚、育儿、创业、管理团队、上市准备等行为 |
| A-05 | 19-30 岁开放 | 应出现事业、投资、感情类行为 |
| A-06 | 31-50 岁中高级行为 | 应出现管理团队/商务谈判/客户开发、投资房产/资产配置/家庭投资等 |
| A-07 | 51-70 岁养老行为 | 应出现养生/退休准备/康复训练等 |
| A-08 | 71+ 岁晚年行为 | 应出现旅行养老/遗产规划/养生等，且不含创业、加班、求职、结婚、买房等高压力青年行为 |
| A-09 | 截图问题回归 | 1 岁行为池不再出现做饭、陪伴父母（旧版人脉标签）、演讲、房屋漏水 |

**运行命令**：

```bash
cd life-grid-demo
npm run test-age
```

### 2.5 保存 / 加载 / 回放测试（test-save-load）

**目标**：确保人生数据可以完整导出、导入、保存到本地，并在加载后精确回放。

**测试文件**：`life-grid-demo/src/test-save-load.ts`

**测试项**：

| 编号 | 测试项 | 通过标准 |
|---|---|---|
| S-01 | 自动运行产生记录 | 自动运行 N 年后，历史记录数为 N |
| S-02 | 导出 JSON | `exportLifeData()` 返回非空合法 JSON |
| S-03 | 导入结构校验 | `importLifeData()` 正确解析，版本、配置、records、snapshots 结构合法 |
| S-04 | 快照数量 | snapshots.length === records.length + 1 |
| S-05 | 回放启动 | `startReplay()` 成功，进入回放模式 |
| S-06 | 回放步数 | 回放步数等于原记录数 |
| S-07 | 回放状态一致 | 回放结束后所有状态属性（年龄、健康、财富、知识、技能、人脉、幸福、魅力、运势、平衡度）与原人生完全一致 |
| S-08 | 非法数据拒绝 | 非法 JSON、版本不匹配、结构缺失均返回 null |
| S-09 | 行为 ID 合法性 | 所有记录中的 behaviorId 都存在于当前行为库 |

**运行命令**：

```bash
cd life-grid-demo
npm run test-save-load
```

### 2.6 坐标系一致性测试（隐含在 UI 测试中）

**目标**：确保 `n1` 在底部、`n10` 在顶部，`l1 ~ l10` 对应 10 大类别。

**检查点**：

| 编号 | 检查点 | 验证方式 |
|---|---|---|
| CO-01 | 终端版 n1 在底部 | `src/ui/grid.ts` 的 `renderGrid` 从 `visualRow = 9` 递减到 `0` 输出 |
| CO-02 | Web 版 n1 在底部 | `src/web/components/grid.ts` 的 `renderGrid` 从 `visualY = 10` 递减到 `1` 插入 DOM |

| CO-04 | 类别顺序正确 | `CATEGORY_ORDER` 为 成长/教育/事业/投资/感情/家庭/社交/兴趣/风险/机遇，对应 l1 ~ l10 |

## 三、验收标准

### 3.1 强制通过项（阻塞性）

以下任何一项失败，均视为未通过验收：

1. `npm run test` 全部通过。
2. `npm run build` 无 TypeScript 错误。
3. `npm run build:web` 成功生成生产包。
4. 1 岁行为池中不得出现做饭、演讲、房屋漏水、买股票、买房、结婚、恋爱、工作、创业、失业、投资失败等成人专属行为。
5. Web 版棋盘渲染必须 `n1` 在底部、`n10` 在顶部。
6. 保存的人生数据（`SavedLifeData`）必须可导入、可回放，且回放后状态与原人生完全一致。

### 3.2 推荐通过项（非阻塞，但应尽量满足）

1. 每个年龄段（1-5、6-12、13-18、19-30、31-50、51-70、71+）可选行为数量 >= 5。
2. 行为 `category` 与 `tags` 语义一致，无错位。
3. 文档（行为数据库.md、核心公式.md、设计文档）与代码实现一致。
4. Web 版在 900px ~ 1200px 宽度下，当前状态与人生日志显示在棋盘右侧。

## 四、测试运行总命令

```bash
cd life-grid-demo

# 运行全部测试
npm run test

# 单独运行某类测试
npm run test-data
npm run test-core
npm run test-ui
npm run test-age
npm run test-save-load

# 构建验证
npm run build
npm run build:web

# 终端 Demo
npm start
```

## 五、新增测试的流程

当新增行为、事件、类别或修改规则时，请按以下流程补充测试：

1. **数据变更**：在 `test-data.ts` 或 `test-age-appropriateness.ts` 中补充断言。
2. **规则变更**：在 `test-core.ts` 中补充对应的核心逻辑断言。
3. **UI 变更**：在 `test-ui.ts` 中补充渲染或交互断言。
4. **坐标系变更**：必须同步检查 `src/ui/grid.ts` 和 `src/web/components/grid.ts` 的渲染方向，并更新本文档 2.5 节。
5. **文档同步**：更新相关 `.md` 文档后，在本文档对应章节确认一致性。

## 六、历史问题回归

以下问题已被修复，后续改动需确保不再复现：

| 问题 | 修复方式 | 回归测试 |
|---|---|---|
| 1 岁出现做饭、演讲、房屋漏水 | 重构 `modern-behaviors.ts`，设定合理年龄范围 | `test-age` A-02、A-09 |
| 1-5 岁不出现「学说话」等教育行为 | 修正 `behavior-pool.ts` 年龄段白名单 | `test-age` A-02 |
| Web 棋盘 n1 显示在顶部 | 修正 `web/components/grid.ts` 渲染顺序 | 本文档 2.6 节、UI 视觉检查 |
| 无法保存/回放人生 | 新增 `SavedLifeData`、快照、回放逻辑、本地存储与文件导入导出 | `test-save-load` S-01 ~ S-09 |
| 文档与代码类别不一致 | 更新 `核心公式.md`、`行为数据库.md` 等 | 人工文档审查 |

## 七、待启用内容的验收要求

末世行为库、穿越行为库等扩展模式当前未启用。启用前必须通过：

1. 数据加载测试：行为数量、年龄段覆盖、事件数量达标。
2. 年龄合理性测试：扩展模式的行为年龄范围符合该模式设定。
3. 坐标系一致性测试：在扩展模式下棋盘渲染方向不变。
4. 回归测试：`npm run test` 全部通过，且不影响现代人生模式。
